# JRenderLab：程序入口、切换作业与单步学习

工程根目录为 `D:\github\JGraphicsLab`。下面先说明你现在为什么看到 HW12，再说明从哪里启动、如何切换和怎样顺着调用栈学习。

## 1. 默认显示什么？改哪里？

打开 [`src/Application/Config.h`](../src/Application/Config.h)。本次完成 HW32～HW50 后，保留你原来的默认配置：

```cpp
// 改这里选择作业，例如 17、29、30 或 31。
inline constexpr int kActiveHomework = 50_3;

// 运行 Homework 时保持 None。
inline constexpr ModelDemo kActiveModelDemo = ModelDemo::None;
```

当前默认是新增 Bunny 资源展示 `50_3`；所有资产入口为 `50_1`～`50_10`，见 [HW50_资源展示](HW50_资源展示.md)。想显示原 HW31 实心立方体，把 **50_3 改为 31**，保存文件，重新编译，然后启动 `JGraphicsLab`。

这是编译期常量：修改源文件后必须重新生成程序；直接双击旧的 `.exe` 仍然会使用旧值。关闭旧窗口后启动刚编译的程序。Visual Studio 中确认选择的是本次构建目录下的 `JGraphicsLab`，而不是 `out/package` 等目录中的旧副本。

如果把 `kActiveModelDemo` 改成 `ModelDemo::Teapot` 等非 None 值，默认就进入模型演示。要恢复作业模式，可以改回 None，或在启动参数中明确指定 `--hw 31`。

HW12 只在像素 `(50,50)` 演示深度覆盖，最终得到一个红色像素。100×100 的帧缓冲放大显示到 600×600 窗口，画面大部分仍然是黑色。这是当前演示内容，不代表模型加载失败。

## 2. 程序入口在哪里？

| 构建目标 | 可执行文件 | 源码入口 | 用途 |
|---|---|---|---|
| `JGraphicsLab` | `JGraphicsLab.exe` | [`RasterWindow.cpp`](../src/Application/RasterWindow.cpp) 的 `wWinMain()` | 图形窗口，同时通过控制台显示数学结果 |
| `JRenderLabCLI` | `JRenderLabCLI.exe` | [`ConsoleMain.cpp`](../src/Application/ConsoleMain.cpp) 的 `wmain()` | 数学输出、一次渲染或图像导出；结束后退出，没有图形窗口 |
| `JRenderLabTests` | `JRenderLabTests.exe` | [`IntegrationTests.cpp`](../tests/IntegrationTests.cpp) 的 `main()` | CTest 验收入口，一般不作为日常作业启动目标 |
| `JRenderLab` | 静态库 | 没有可执行入口 | 保存共享实现，被上面三个程序链接 |

入口不在各个 `HWxx.cpp` 中。每个 HW 文件里的 `TestHWxx()`、`RenderHWxx()` 是注册给调度器的回调；图形辅助函数也可以继续单步进入。

当前源码树中没有旧的根级 `src/main.cpp`、`src/Renderer.cpp`、`src/RasterWindow.h` 文件；直接查看上述 Application 入口和分模块实现。

## 3. 不改源码也能切换作业

在工程根目录打开 PowerShell，已经使用 `out/modular` 构建过时可执行：

```powershell
Set-Location 'D:\github\JGraphicsLab'

# 显示线框立方体。
& '.\out\modular\Debug\JGraphicsLab.exe' --hw 29

# 显示齐次裁剪演示。
& '.\out\modular\Debug\JGraphicsLab.exe' --hw 30

# 显示实心立方体。
& '.\out\modular\Debug\JGraphicsLab.exe' --hw 31

# 只查看三维向量的实际值、预期值与 PASS/FAIL。
& '.\out\modular\Debug\JRenderLabCLI.exe' --hw 17

# 列出所有作业状态。
& '.\out\modular\Debug\JRenderLabCLI.exe' --list

# 执行所有已经有数学测试回调的作业。
& '.\out\modular\Debug\JRenderLabCLI.exe' --all-tests
```

`--hw N` 覆盖 `Config.h` 的默认选择，运行时切换不需要重新编译，但程序本身必须已经包含最新源码。

| 选择 | 实际表现 |
|---|---|
| `--hw 0` | 全部已有数学测试通过后，绘制 HW31；CLI 绘制到内存后退出，窗口版显示结果 |
| `--hw 12` | 一个红色像素的深度覆盖演示 |
| `--hw 17` | 三维向量的 9 项数学检查；没有作业绘图回调 |
| `--hw 21` | 二维变换的数学检查，以及灰色/白色四边形对照 |
| `--hw 29` | 数学检查及固定旋转姿态的白色线框立方体 |
| `--hw 30` | 数学检查及近裁剪面三角形演示 |
| `--hw 31` | 数学检查及有深度遮挡的彩色实心立方体 |
| HW32～HW50 | 已实现，每章同时输出数值检查及 600×600 中文对照图，窗口内左右方向键切章 |
| HW01 | 当前未实现，提示状态并以非零退出码结束；不会伪造 PASS |

数学作业 HW16～HW20、HW22～HW28 没有图形回调。使用窗口版运行它们时要查看控制台；黑色图形窗口属于正常情况。不要为了看到图形而把所有数学作业都改成加载 OBJ。

## 4. 从 Visual Studio 启动与调试

如果通过 CMake 生成的 `.sln` 打开工程：

1. 选择 `Debug` 和 `x64`。
2. 图形作业以 `JGraphicsLab` 作为启动项目，数学输出以 `JRenderLabCLI` 作为启动项目。不要选择静态库 `JRenderLab`。
3. 可以直接修改 `Config.h` 后生成。也可以在启动项目的“属性 → 配置属性 → 调试 → 命令参数”中设置 `--hw 31`。
4. 按 F5 启动带断点的程序；不需要调试时用不调试启动。

如果在 Visual Studio 中以“打开文件夹/CMake”的方式使用工程：选择 `JGraphicsLab.exe` 或 `JRenderLabCLI.exe` 作为启动目标；参数由所选目标的调试配置提供。具体输出目录由当前 CMake 配置决定，可能在 `out/build/x64-debug`，不一定是本文示例的 `out/modular/Debug`。

如果调试配置残留 `--hw 12`，它会覆盖你刚改成 31 的 `kActiveHomework`，因此仍看到 HW12。想按源码默认值启动，应清空 `--hw`、`--demo` 等选择参数。选择器 `--hw` 与 `--demo` 同时出现时，最后出现的选择生效。

推荐的断点位置：

- 程序首次进入：`RasterWindow.cpp::wWinMain()` 或 `ConsoleMain.cpp::wmain()`。
- 参数与默认值：`Application.cpp::ParseArguments()`，观察 `options.homework`、`options.demo`。
- 调度：`InitializeApplication()`、`Runner.cpp::RunMathHomeworkTest()`、`RunHomework()`。
- 本章：`src/Homework/HW17.cpp::TestHW17()` 或 `HW31.cpp::RenderHW31()`。
- 算法：例如 `Core/Math.cpp::Cross()`、`Renderer/DepthBuffer.cpp::DepthTest()`。

使用 F10 看本层执行顺序，F11 进入公共算法，Shift+F11 返回上一层。函数重载较多，给向量或矩阵函数设置断点时确认参数类型。使用 Debug 查看变量；Release 优化后有些局部变量可能不可见。

## 5. 一次普通作业启动的真实调用流程

以下以没有 `--all-tests`、没有 `--list`、没有模型演示选择的普通 `--hw N` 启动为例。

```text
wWinMain（窗口）或 wmain（控制台）
  -> ParseArguments
       ApplicationOptions 从 Config.h 取得默认编号
       若有 --hw N，则覆盖默认编号，并选择作业模式
  -> InitializeApplication
       -> FindHomework(N) 查注册表
       -> 若本章有 test 回调：RunMathHomeworkTest(N) -> TestHWxx()
       -> RenderApplicationFrame
            -> RunHomework(N, false)
                 -> 清空颜色与深度
                 -> 若本章有 render 回调：RenderHWxx()
       -> 若有 --output：保存帧缓冲
  -> 窗口版创建窗口，WM_PAINT 显示 GetApplicationDisplaySurface()
       原作业使用 Raster::Pixels()；HW32～50 使用独立中文学习画布
     控制台版返回退出码并结束
```

窗口的绘图算法在初始化阶段写入内存；`WM_PAINT` 主要把内存中的图像显示出来，不重新执行全部数学测试。普通作业默认不是每帧循环绘制。

`RunHomework(N, false)` 中的 false 表示数学检查已经在初始化时执行，不重复运行；如果直接手动调用 `RunHomework(N)`，默认会先执行该章检查。测试失败时普通初始化返回失败，不继续绘制。

注册位置：[`Homework/Registry.cpp`](../src/Homework/Registry.cpp)。每条记录保存编号、名称、类型、测试函数、渲染函数和实现状态。`FindHomework()` 的显式 switch case 返回对应记录；选择作业时只改 Config 或启动参数，不需要再去改 switch。

`RenderScene()` 目前是 `Application.cpp` 中的兼容包装，调用 `InitializeApplication(ApplicationOptions{})`。现有两个可执行入口直接调用初始化函数，不依赖旧的 `main.cpp` 或单文件 Renderer。

## 6. HW12 和 HW17 的单步示例

### HW12：为什么最后只留下红色？

打开 [`HW12.cpp`](../src/Homework/HW12.cpp)，在 `RenderHW12()` 与公共 `DepthTest()` 中设置断点：

```text
ClearDepthBuffer：每个像素深度设为 1
DepthTest(50,50,0.8)：0.8 < 1，保存 0.8，PutPixel 写蓝色
DepthTest(50,50,0.2)：0.2 < 0.8，保存 0.2，PutPixel 写红色
最终 depthBuffer[50][50] = 0.2，像素是红色
```

更小的深度代表更近；深度相等时严格小于条件不成立，不会覆盖。HW12 当前没有把重叠三角形作为完整图形案例，这一点在文件顶部注释中明确标出。

### HW17：函数进入后怎样得到 32？

使用 CLI 运行 `--hw 17`，在 [`HW17.cpp`](../src/Homework/HW17.cpp) 的 `TestHW17()` 设置断点，然后进入 `Dot(Vec3,Vec3)`：

```text
Dot((1,2,3),(4,5,6))
  = 1*4 + 2*5 + 3*6
  = 4 + 10 + 18
  = 32
MathTestContext::near(实际32,预期32) -> true
MathTestContext::check(true,说明) -> PASS，累加 passed
```

`MathTestContext` 位于 `Homework/TestSupport.cpp`，统一输出比较结果。数值比较检查有限性，并采用绝对误差容限 `1e-4`；各章没有再复制自己的公共比较算法。本章最后返回 `TestResult{passed,failed}`。

## 7. HW31 的模型到像素过程

[`HW31.cpp`](../src/Homework/HW31.cpp) 的入口为 `RenderHW31()`。它调用 `DrawSolidCubeMVP(1.2f)`，使用内置教学 Cube 数据，不读取 `cube.obj`。

```text
RenderHW31
  -> DrawSolidCubeMVP
       -> 首次创建静态 Mesh（8 顶点、12 三角形、原 6 面色）
       -> MakeModelMatrix，建立旋转姿态
       -> DrawMesh(mesh, model, Camera{}, options)
            -> P * V * M * Position
            -> ClipTriangleToFrustum（六平面齐次裁剪）
            -> 裁剪多边形拆成三角扇
            -> MakeScreenVertex3D
                 PerspectiveDivide -> ViewportTransform
            -> RasterizeTriangle3D
                 边函数/覆盖规则 -> 重心坐标
                 -> NDC 深度插值 -> 映射 [0,1]
                 -> DepthTest
                 -> InterpolateColor -> PutPixel
```

三维算法位于 `Renderer/Clipping.cpp`、`Rasterizer3D.cpp`、`DepthBuffer.cpp` 和 `MeshRenderer.cpp`。每个 HW 文件负责组织本章调用，公共算法只有一个实现位置。

## 8. 如何运行 OBJ 模型演示？

模型演示与作业编号分开，启动时用 `--demo`：

```powershell
& '.\out\modular\Debug\JGraphicsLab.exe' --demo cube
& '.\out\modular\Debug\JGraphicsLab.exe' --demo teapot --animate
& '.\out\modular\Release\JGraphicsLab.exe' --demo bunny
& '.\out\modular\Release\JGraphicsLab.exe' --demo dragon

# 导出图像，目录应事先存在。
& '.\out\modular\Release\JRenderLabCLI.exe' --demo teapot --output out/teapot.ppm
```

也可以修改 Config：

```cpp
inline constexpr ModelDemo kActiveModelDemo = ModelDemo::Teapot;
```

可选枚举为 None、Cube、Teapot、Bunny、Dragon。模型只在初始化时加载一次，并自动居中与缩放。`--animate` 只控制模型演示的定时旋转，不会使当前固定姿态的 HW29/HW31 自动动画。

资源位置由可执行文件目录和编译时资源目录解析，与 Visual Studio 当前工作目录无关。保存图像的相对 `--output` 路径则相对于你启动程序时的工作目录；这是输出文件路径，不是资源查找规则。

## 9. 如何重新构建？

在工程根目录执行以下命令，指定的输出目录就是本文示例使用的 `out/modular`：

```powershell
cmake -S . -B out/modular -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build out/modular --config Debug --parallel 4
cmake --build out/modular --config Release --parallel 4
```

已有这个构建目录时，修改 Config 后只需重新 `cmake --build`。数学及图形验收可运行：

```powershell
ctest --test-dir out/modular -C Debug --output-on-failure
```

## 10. 每章说明放在哪里？

`src/Homework/HW01.cpp` 到 `HW50.cpp` 的顶部已加入独立中文学习说明，内容包括：

- 本章状态、配置编号、测试/绘制调度路径。
- 当前入口实际调用的函数及其执行顺序。
- 数学公式、默认输入和逐步计算示例。
- 最终图像或数值，以及适合设置断点的变量/算法文件。
- 当前实现的限制；未实现章节区分理论目标与当前占位函数。

每个本章入口函数上方也有简短说明，便于从定义处开始阅读。原作业的学习说明仅增加注释，没有改变作业算法与测试条件；资源展示使用独立的 HW50_1～HW50_10 入口。

更多工程结构与限制见 [重构与使用](重构与使用.md)，原函数位置见 [函数迁移清单](函数迁移.md)。

HW32～HW50 的逐章图像、关键算法、计算示例和断点路线见 [新增章节学习指南](HW32至HW50_学习指南.md)。这些章节的源文件已从占位入口改为实际实现；其余原作业算法未修改。
