# 从 OBJ 到布林冯渲染：原项目函数补全卷

这份卷子只对应当前项目里**已经存在**的 `.cpp` 函数。按 01→24 的顺序，把函数体中的 `TODO(题 NN)` 和 `throw std::logic_error(...)` 替换成自己的实现；不需要新建函数、类、绘图练习或独立程序。头文件接口、CMake、窗口入口、资源路径和原有运行方式已经保留。

完成目标：原项目读取 OBJ/MTL/贴图，经过模型、观察、透视投影、齐次裁剪、三角形光栅化、深度测试、透视正确插值、贴图采样和 Blinn–Phong 光照，最终在现有窗口显示模型，或用现有命令行导出 PNG。这里的 Blinn–Phong 是**光栅化管线中的局部光照**，没有光线追踪。

## 先认清现有调用链

`src/application/main.cpp` → `RenderScene` → `OBJLoader::LoadAsset` → `DrawModelShaded` → `DrawShaded` → `ClipTriangleToFrustum` → `Transform::ToScreen` → `RasterizeTriangleShaded` → `RasterizeCoveredTriangle` → `Material::Evaluate` → `Raster::PutPixel`。

`RenderScene`、`DrawModelShaded`、`RasterizeTriangleShaded`、`Material::Evaluate`、窗口、WIC 图片解码与保存、基础向量/矩阵运算均已在原项目中；本卷只挖空它们所依赖的关键实现。你之前在 `FrameBuffer.cpp` 写过的 `PutPixel`、`DepthTest`、线性颜色与 sRGB 转换保留，无需重写。请直接在原函数体里写，不要改签名。每题完成后可以继续下一题；全部完成后再从原来的 `JGraphicsLab` 入口运行。

## 写的时候要能回答

1. OBJ 的同一个位置为什么可能对应多个 UV/法线？为什么不能只用位置索引去重？
2. `P·V·M` 的概念顺序与本项目 `P * V * M * v` 的代码顺序如何对应？法线为什么不能直接乘 Model？
3. 为什么必须先在齐次空间裁剪，再除以 `w`？过近裁剪面的三角形会变成什么？
4. 像素中心 `(x+0.5, y+0.5)`、Top-left 规则、退化三角形和屏幕边界分别怎样影响覆盖？
5. 深度为什么用屏幕重心插值 `ndcZ` 并映射到 `[0,1]`，而 UV/世界位置要用 `1/w` 修正？
6. sRGB 图像为什么先转线性空间再做插值和光照，最终写帧缓冲时又转回 sRGB？
7. Flat、Gouraud、Phong 是着色**频率**；Lambert、Blinn–Phong 是光照**公式**。它们在现有两个枚举里如何组合？
8. 方向光和点光源的 `L`、光强有何区别？为什么高光用半程向量而漫反射用 `N·L`？

这些问题都对应上表中的现有函数，不要求加入 MSAA、阴影射线、反射、BVH 或路径追踪。

## 最终回到原项目运行

完成 24 题后，在 Visual Studio 中打开仓库根目录的 `CMakeLists.txt`，选择原来的 `JGraphicsLab` 目标并点击运行。默认模型和材质由 `src/application/Renderer.h` 的 `kDefaultModelPath`、`kDefaultMaterial`、`kDefaultLightingModel` 控制；窗口菜单还能切换 Cube、Bunny、Viking Room、材质与 Lambert/布林冯。

也可用原程序的命令行入口导出图像（把可执行文件路径替换为自己构建目录中的实际路径）：

```powershell
& '你的构建目录\JGraphicsLab.exe' --headless --model room --material auto --lighting blinn-phong --output '你的输出目录\room.png' | Out-Host
```

验收看三件事：模型几何和遮挡正确；Viking Room 的 OBJ 原配 UV/MTL/贴图对齐；切换 Lambert 与布林冯时高光有预期差别。若某个 `TODO(题 NN)` 尚在运行路径中，现有异常会明确指出题号。
