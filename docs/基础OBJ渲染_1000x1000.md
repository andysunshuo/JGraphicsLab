# 基础 OBJ 变换与光栅化：1000×1000

2026-10-15，当前分支 `renderer-from-scratch`。本次只修复基本 OBJ 显示流程：不加载材质、不计算光源，不接入纹理和光线追踪。

## 为什么之前失败

1. `Mat4::Identity()` 是静态函数，返回一个新矩阵。原来的 `Mat4 result; result.Identity();` 丢弃返回值，result 仍是零矩阵。Translation、Scale、三轴 Rotation 和 LookAt 因此缺少必须的单位元素，MVP 的 w 可能为零，或所有顶点挤在一起。现已改为接收返回值，保留其余已写的公式。
2. Transform::ToScreen 原先将 Y 翻转，PutPixel 又翻转显示内存行号，方向不符合左下原点约定。现在屏幕 Y 向上，只在写入显示内存时翻转一次。
3. RasterizeTriangle 原先只画三个顶点，尚未执行三角形面积覆盖。现在遍历屏幕包围盒、使用像素中心与 Top-left 规则填充，并做深度测试。
4. OBJLoaderTests 原先没有链接 Renderer 新调用的数学/Transform/Camera 源码，产生六个 LNK2019 和 LNK1120。程序和测试现在链接同一个 JRenderBasic 静态库，使用同一份真实颜色/深度缓冲。
5. 六份数学源与 Camera 源中有 GBK 中文注释，但工程使用 `/utf-8`。已转换为 UTF-8，未重写其中正确的向量和矩阵运算公式。
6. 旧流程在透视除法前没有完整裁剪。现在复用当前声明的裁剪接口，实现六个齐次平面裁剪，近面相交的三角形可以保留可见部分。

## 现在如何运行

Visual Studio 选择 **JGraphicsLab.exe** 作为启动目标，然后重新生成并按 F5。不要选择静态库 JRenderBasic。默认显示旋转的实心 Cube OBJ。

现有 IDE 构建目录：

```powershell
& 'D:\github\JGraphicsLab\out\build\x64-debug\JGraphicsLab.exe'
```

也可以使用已验证的独立构建目录：

```powershell
Set-Location 'D:\github\JGraphicsLab'
cmake -S . -B out/repair -G 'Visual Studio 17 2022' -A x64
cmake --build out/repair --config Debug --parallel 4
& '.\out\repair\Debug\JGraphicsLab.exe'

# 选择现有模型，或传入自己的 OBJ 路径。
& '.\out\repair\Debug\JGraphicsLab.exe' --model triangle
& '.\out\repair\Debug\JGraphicsLab.exe' --model icosahedron
& '.\out\repair\Debug\JGraphicsLab.exe' --model 'D:\models\example.obj'

# 不开窗口，经过同一入口渲染并导出；输出目录需存在。
& '.\out\repair\Debug\JGraphicsLab.exe' --headless --model cube --output out/cube.ppm
```

真正的颜色缓冲、深度缓冲和视口现在是 **1000×1000**，每幅图像一百万像素。初始窗口按桌面大小适配；缩小窗口只是显示缩放，不会把实际光栅化分辨率降回 100×100。

## 从哪里改参数、设置断点

- `src/RasterWindow.h`：WIDTH、HEIGHT。
- `src/application/Renderer.h`：kDefaultModelPath，当前为 `assets/models/cube.obj`。
- `src/application/Renderer.cpp::RenderScene()`：Camera 的 eye/target、FOV、Near/Far，以及模型旋转。当前用包围盒自动居中、等比缩放到最长边 1.8，再旋转。
- `src/math/Transform.cpp`：保留 Model=`T*Rz*Ry*Rx*S`、列向量、右手系、Projection*View*Model 的约定。
- `src/renderer/Rasterizer.cpp::DrawMeshBasic()`：组织顶点、面色和完整流水线。
- `src/renderer/TriangleRasterizer.cpp`：裁剪、重心、覆盖、颜色插值和深度。
- `src/renderer/FrameBuffer.cpp`：实际固定尺寸的颜色/深度存储与 PPM 导出。
- `src/application/main.cpp::wWinMain()`：启动参数、渲染初始化、窗口消息与 WM_PAINT。

模型只在首次选定路径时加载，重复绘制复用缓存；切换模型替换缓存，缓存不无限增长。资源依旧优先从 exe 旁 assets 查找，源目录作为开发回退。面颜色只是区分几何的固定色板，不是光照结果。

## 实际调用流程

```text
wWinMain → 解析参数 → RenderScene
  → OBJLoader（已有 tinyobjloader，统一位置/UV/法线索引）
  → 包围盒自动居中/缩放 → Model
  → Camera View/Projection
  → DrawMeshBasic：P*V*M*Position
  → ClipTriangleToFrustum（x±w、y±w、z±w 六平面）
  → 三角扇拆分 → 透视除法 → 左下原点视口
  → RasterizeTriangle：包围盒 → 像素中心 → Top-left → 重心坐标
  → NDC 深度线性插值 → [0,1] → 严格小于的 DepthTest
  → 面色/顶点色 → Framebuffer
  → WM_PAINT 或 SavePPM
```

所有包围盒在转整数前限制到屏幕范围；非有限坐标、无效索引和退化三角形不会写出界。裁剪临时多边形有数量限制。原 OBJ 文件及其加载预算保留，不删除模型几何。
