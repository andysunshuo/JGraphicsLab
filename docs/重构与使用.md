新增资产浏览入口为 `50_1`～`50_10`，当前 Config 默认选择 `50_3`。可以直接写 `kActiveHomework = 50_10`；对应表与资源含义见 [HW50_资源展示](HW50_资源展示.md)。这些扩展不修改原 HW01～HW50。

## 保留的约定

- 右手坐标系，相机沿局部负 Z 方向观察。
- 矩阵存储为 `m[row][column]`，使用列向量，`clip = P * V * M * position`。
- 位置的齐次分量为 1，方向为 0；角度参数使用弧度。
- OpenGL 风格六平面裁剪：`-w <= x,y,z <= w`，NDC 深度为 `[-1,1]`。
- 深度写入前映射到 `[0,1]`，越小越近，保持原来的严格小于比较。
- 帧缓冲仍为 100×100，X 向右、Y 向上，像素原点在左下角；显示内存从上往下存储。
- 视口边界为 `[0,width]×[0,height]`，像素中心为 `(x+0.5,y+0.5)`；三维共享边覆盖规则保持原实现。

## 构建与运行

在工程根目录的 PowerShell 中执行：

```powershell
cmake -S . -B out/modular -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build out/modular --config Debug --parallel 4
ctest --test-dir out/modular -C Debug --output-on-failure -R "数学|Cube"
ctest --test-dir out/modular -C Debug --output-on-failure -R "Bunny"
cmake --build out/modular --config Release --parallel 4
ctest --test-dir out/modular -C Release --output-on-failure
```

需要 Visual Studio 2022 的 C++ 桌面开发组件和 Windows SDK。CMake 最低版本为 3.20，C++20。源码已从 GBK 转为 UTF-8，MSVC 统一使用 `/utf-8`。首次配置后，构建无需联网；tinyobjloader 的固定版本、文件校验值及许可证已保存。

原来的 `JGraphicsLab` 是图形窗口程序；新增 `JRenderLabCLI` 是一次运行后退出的控制台程序。

```powershell
# 修改 Config.h 的 kActiveHomework 也可以保留原来的编译期选择习惯。
.\out\modular\Debug\JRenderLabCLI.exe --hw 17
.\out\modular\Debug\JGraphicsLab.exe --hw 29
.\out\modular\Debug\JGraphicsLab.exe --hw 30
.\out\modular\Debug\JGraphicsLab.exe --hw 31
.\out\modular\Debug\JRenderLabCLI.exe --all-tests
.\out\modular\Debug\JRenderLabCLI.exe --list

# 模型演示不占用作业编号。
.\out\modular\Debug\JGraphicsLab.exe --demo cube
.\out\modular\Debug\JGraphicsLab.exe --demo teapot --animate
.\out\modular\Release\JGraphicsLab.exe --demo bunny
.\out\modular\Release\JGraphicsLab.exe --demo dragon

# 无窗口导出原始 100×100 图像。PPM 可使用常见图像工具查看。
.\out\modular\Release\JRenderLabCLI.exe --demo teapot --output out/teapot.ppm
```

也可以在 `Application/Config.h` 中设置 `kActiveModelDemo`。`--hw`、`--demo` 同时出现时，后出现的选择生效。`--animate` 只用于模型演示；HW29/HW31 保持原来固定角度 `1.2` 的默认图像，各演示函数仍接受手动角度参数。窗口 Math 作业通过控制台输出实际值、预期值及 PASS/FAIL。未实现作业输出“未实现（Not Implemented）”并返回非零退出码。

## Mesh 与模型管线

```cpp
#include "Assets/ObjLoader.h"
#include "Assets/ResourcePaths.h"
#include "Renderer/MeshRenderer.h"

// 只在初始化时加载一次，并保存 loaded 供后续帧复用。
auto loaded = Assets::LoadObj(Assets::Resolve("Models/teapot.obj"));
if (!loaded) {
    std::fprintf(stderr, "%s\n", loaded.error.c_str());
    return;
}
Camera camera;
camera.eye = {1.7f, 1.3f, 3.0f};
camera.fovRadians = 1.04719755f;
camera.nearPlane = 0.1f;
camera.farPlane = 20.0f;
Mat4 model = MakeAutoFitModel(loaded.mesh); // 也可以直接提供手动模型矩阵。
RenderOptions options;
options.colorMode = MeshColorMode::FaceNormal;
DrawMesh(loaded.mesh, model, camera, options);
```

`Vertex` 保存位置、法线、UV，`Mesh` 保存统一顶点和三角形索引，可额外保存逐三角形颜色。Loader 使用 tinyobjloader 解析与三角化，按 `(位置索引,法线索引,UV索引)` 去重，正确保留法线硬边和 UV 接缝；缺失属性初始化为零。只保留被三角形引用的顶点，因此顶点数量可能略少于文件记录数，三角形不被删减。

`DrawMesh` 使用现有数学函数，依次执行 Model、View、Projection、`ClipTriangleToFrustum`、透视除法、视口和 `RasterizeTriangle3D`。HW31 只将场景组织改为 Mesh，原来的顶点、面色、索引顺序和相机参数保持不变。HW29、HW30 的演示函数保持原实现。

模型演示的四个缓存槽只加载一次，加载失败也会缓存错误。包围盒与自动居中缩放矩阵只在初始化时计算，后续帧复用。所有模型的最长边映射到 1.5，不改写原顶点；默认只绕 Y 轴旋转，不擅自改变模型朝向。每次 `DrawMesh` 返回输入三角形数、光栅化三角形数、拒绝数和耗时。默认清空深度缓冲；绘制多物体时第二个物体起可设置 `clearDepth=false`。

资源先从可执行文件旁的 `Assets` 查找，再回退到编译时工程资源目录，不读取当前工作目录。`cmake --install out/modular --config Release --prefix out/package` 可将程序和资源一起部署。显式绝对路径也可直接交给 Loader。

## 安全与限制

默认 OBJ 预算：文件 64 MiB，单行 64 KiB，位置 50 万，法线与 UV 合计 100 万，统一顶点 150 万，三角形 50 万。解析前检查预算，读取期间也限制字节数，转换期间再次检查索引与数量。临时裁剪多边形的大小仅由一个三角形与六平面相交决定。整个大模型完整进入渲染，不偷偷删面或降采样。

非法位置、法线、UV 索引会返回带路径的错误并清空部分结果；渲染拒绝非法索引、非有限坐标和退化三角形。屏幕顶点在进入原光栅化整数包围盒转换前再次检查，三维包围盒和 `PutPixel` 保持原边界保护。

- 原二维算法中的边界输入行为和残留 TODO 学习注释保持不变；本次不宣称它们已对所有任意输入完善。原 `DrawCircleOutline`/`FillCircle` 的循环坐标在非对称圆心下也保持原行为，避免修改作业算法。
- 保留 100×100 教学分辨率和原来二维 MSAA 限制；没有新增三维 MSAA、PBR、阴影、纹理着色、法线矩阵或透视正确 UV 插值。
- 面法线颜色展示的是模型空间面法线，不是世界空间照明。Loader 保存的顶点法线和 UV 供后续作业使用。
- 当前不读取 MTL、不渲染 OBJ 线段/点图元；含混合图元的 OBJ 只集成三角形几何。多边形使用 tinyobjloader 内置三角化，复杂凹多边形不作全面正确性保证；已准备的四个模型全部是三角形。
- `TextureLoader` 使用 Windows WIC 解码 PNG/JPEG 等常规图像，不负责 HDR 解码或纹理采样。新增 `HdrLoader` 为 HW50_10 解码 HDR 环境预览。纹理预算为 64 MiB、单边 8192、总像素 16×1024×1024。
- 窗口与纹理解码目前依赖 Windows，帧缓冲仍是单线程全局教学状态，不能同时从多线程绘制不同窗口。
- 大模型的 Debug 渲染较慢。计时直接记录全几何执行，不承诺实时帧率。

## HW32～HW50 的共享扩展

新增 `Geometry/Surface`（法线、法线矩阵、UV 几何）、`Renderer/ImageProcessing`（线性图像、卷积、采样、Mipmap）、`Renderer/LearningPipeline`（属性光栅化与光照）、`Homework/LearningDemos`（学习场景与中文画布）。新管线使用动态尺寸 RenderTarget，复用原向量/矩阵、六面齐次裁剪、深度比较和 Top-left 判定；原 HW31 的 100×100 输出保持原路线。`ClipVertex` 新增属性由原裁剪交点函数同步插值。

`AdvancedHomeworkTests` 是新增的第五项 CTest，逐章检查数值、实际应用调度及画布导出，并检查 UV 裁剪、非法索引和缓冲预算。原作业与资源展示四项验收继续保留。
