# 头文件接口与 .cpp 实现顺序

本次按你的新目录补齐项目自有 `.h`，只增加数据结构、接口声明及中文实现注释。第三方 tinyobjloader 头文件保持原样；项目全部 19 个 `.cpp` 与当前三个资产文件均通过修改前后 SHA-256 核对，内容不变。

新声明的函数等待你在 `.cpp` 中实现。头文件可以编译，不代表这些算法已经完成；当前窗口仍显示原三点演示。每个头文件顶部说明实现位置，函数前的注释说明公式、步骤、边界条件与调用关系。

## 建议实现顺序

| 顺序 | 头文件 | 你在 .cpp 中要写的内容 | 首个手算或断点检查 |
|---|---|---|---|
| 1 | `math/Vec2.h`、`Vec3.h` | 分量运算、点积、叉积、长度、归一化、插值；零长度处理 | Vec3 点积 `(1,2,3)·(4,5,6)=32`，X×Y=Z |
| 2 | `math/Vec4.h` | 四维运算、位置 w=1/方向 w=0、受检查的透视除法 | `(2,4,6,2)` 除 w 得 `(1,2,3,1)`，w=0 拒绝 |
| 3 | `math/Mat3.h`、`Mat4.h` | 单位矩阵、矩阵乘法、矩阵乘列向量、转置、受检查求逆 | Identity*v=v；先平移再缩放与反过来不一样 |
| 4 | `math/Transform.h` | Model、LookAt、投影、法线逆转置、带属性视口变换 | 非均匀缩放后的法线仍垂直于变换后的切线 |
| 5 | `scene/Camera.h` | 转调公共变换函数，组合 VP；逆 VP 生成世界射线 | 中央像素射线接近相机视向；上下像素方向正确 |
| 6 | `geometry/Mesh.h` | 校验索引、包围盒与面积加权法线；以后新增 `Mesh.cpp` 并登记 CMake | 全在正坐标的模型包围盒不应错误包含原点 |
| 7 | `RasterWindow.h`、`renderer/FrameBuffer.h` | 在 FrameBuffer.cpp 写颜色编码、目标分配、逐样本深度和 Resolve | depth 0.3 覆盖 0.8，等深度不覆盖；四样本颜色平均 |
| 8 | `renderer/TriangleRasterizer.h` | 新的边函数/重心、Top-left、齐次裁剪、透视属性插值、完整光栅化 | 两三角形共享边不重复/不漏；近面裁剪保留 UV |
| 9 | `scene/Light.h`、`material/Material.h` | 世界空间光向、衰减、Lambert 和 Blinn-Phong；着色调用公共实现 | 正对光更亮，背光只留环境项，指数增大高光变窄 |
| 10 | `material/Texture.h` | 读图、UV/V 翻转、最近邻、双线性、Mipmap、LOD/三线性 | 2×2 四色纹理中心得到线性 RGB `(0.5,0.5,0.5)` |
| 11 | `renderer/Rasterizer.h` | 串起 Mesh→MVP→裁剪→除 w→视口→光栅化→深度→Resolve | 先完整画 Cube，再接 OBJ；不要每帧重新加载 |
| 12 | `raytracing/Ray.h`、`BVH.h` | 先写唯一射线三角形求交，再写箱求交、构建和最近命中遍历 | BVH 与暴力遍历得到同一最近命中，轴平行射线不除零 |

Vertex.h 只保存模型、裁剪与屏幕阶段的数据，不需要 .cpp。OBJLoader.h 对应已有实现，接口不改。Application 的 Renderer.h 声明已有 RenderScene，方便你以后替换手写声明。

## 不重复实现公共算法

向量/矩阵只在 math 实现；Camera 只调用 Transform。模型法线计算放 Mesh，法线变换复用 Mat3 求逆。光照只放 Material/Light，Flat/Gouraud/Phong 只改变计算位置。纹理过滤只在 Texture，材质和管线调用采样接口。BVH 只调用 Ray 中的三角形求交，不再复制公式。

矩阵按 `m[行][列]` 存储，但向量按列向量运算；MVP 为 `P*V*M`。右手系、相机自身 -Z 为前方、NDC 深度 [-1,1]、像素左下原点、显示内存从上到下。角度用弧度，UV 的 V 向上。线性颜色参与光照与滤波，显示前编码为 sRGB。默认矩阵是零矩阵，需要显式 Identity。

## 与现有代码的兼容

`src/rasterizer` 中保留三个只有 include 的兼容头，将现有 .cpp 使用的旧路径转发到新头文件；不会维护第二套算法。当前三参数 RasterizeTriangle 和旧 ToScreen 保留已有行为，新光栅化声明使用独立 RasterizeTriangle3D。

CMake 已跟随你的文件移动更新路径，移除不存在的 src/render 引用，并列入现有空 .cpp。没有修改这些 .cpp；你以后填入实现即可参与编译。新增 geometry/Mesh.cpp 时仍需加入 CMake 源文件列表。若用 WIC 实现纹理解码，还需给使用该实现的目标链接 windowscodecs、ole32。

头文件可独立且重复包含，23 个头文件的 MSVC C++20 独立语法检查及组合检查通过。Debug/Release 现有演示的构建与 OBJ 回归通过。新声明被实际调用后，尚未实现的函数会报链接错误，这是你继续实现 .cpp 时的待办，不是已经完成的功能。

## 资产为何没有同步

原 `.gitignore` 的 `*.obj` 同时匹配 C++ 编译目标与 Wavefront 模型，导致当前三个模型从未进入 Git 跟踪。

已在 `.gitignore` 末尾加入根目录 `assets/**` 与 `Assets/**` 的例外，允许模型、纹理、法线图和环境图进入提交，同时继续忽略 out/build 内的编译产物。当前目录只有 triangle.obj、cube.obj、low_poly_icosahedron.obj 三份模型，现均会出现在 Git 的未跟踪文件列表。

修改 ignore 不会自动把文件提交。你手动提交时，需勾选 `.gitignore`、`assets` 内的模型及本次头文件/工程文件；提交后再推送到远程，家中电脑 pull 同一分支才会获得资产。

可以先只读检查：

```powershell
git status --short --untracked-files=all -- assets
git ls-files --others --exclude-standard -- assets
```

本次没有执行 git add、commit 或 push。历史上没有提交的其他资产不会凭修改 ignore 自动恢复；需要先放入 assets 再纳入你的手动提交。
