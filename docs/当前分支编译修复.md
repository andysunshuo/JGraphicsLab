# 当前分支编译与运行

本次修复的是 `renderer-from-scratch` 分支。完整 HW01～HW50 工程在 `main` 分支；当前分支保留早期 OBJ 顶点显示实验，入口和目录与完整工程不同。

## 启动方法

Visual Studio 打开工程文件夹后，重新生成 CMake，选择 `JGraphicsLab.exe` 作为启动目标，再按 F5。现有 x64 Debug 输出已经重建，可直接运行：

```powershell
& 'D:\github\JGraphicsLab\out\build\x64-debug\JGraphicsLab.exe'
```

独立生成的 Debug 和 Release 程序也已编译验证：

```powershell
Set-Location 'D:\github\JGraphicsLab'
cmake -S . -B out/repair -G 'Visual Studio 17 2022' -A x64
cmake --build out/repair --config Debug --parallel 4
cmake --build out/repair --config Release --parallel 4
& '.\out\repair\Debug\JGraphicsLab.exe'
```

本分支没有 `kActiveHomework` 配置。程序入口是 `src/main.cpp::wWinMain()`，调用 `src/Renderer.cpp::RenderScene()`，加载 `assets/models/triangle.obj` 后执行 `ToScreen()`、`RasterizeTriangle()`。

当前 `RasterizeTriangle()` 是顶点演示：只显示红、绿、蓝三个顶点，没有填充三角形。这是保留的原行为。实际像素为左下坐标 `(25,25)` 红色、`(75,25)` 绿色、`(50,75)` 蓝色，100×100 帧缓冲放大到 600×600 窗口。

## 修复内容

1. 删除错误且重复的 Mesh 定义，先定义 Vec2、Vertex，再定义 Mesh；索引类型使用整数。
2. CMake 加入 `TriangleRasterizer.cpp`，解决后续链接阶段找不到实现的问题。
3. 头文件中的 `ToScreen()` 改为 inline，避免多个源文件包含后重复定义。
4. 使用工程已准备的 tinyobjloader 替代旧解析代码，处理 `v/vt/vn`、`v//vn`、缺失属性、负索引和多边形三角化；独立索引组合映射为统一顶点。
5. 资源优先从 exe 旁读取，源目录作为开发回退；构建自动复制 assets。切换 Visual Studio 工作目录不会影响模型加载。
6. 模型索引与属性数量、文件预算及有限坐标检查；绘制前过滤屏幕外和非有限坐标，避免非法浮点转整数。加载失败返回空 Mesh，启动入口显示中文错误。
7. main.cpp、Renderer.cpp 转为 UTF-8，CMake 指定 MSVC `/utf-8`；使用 tinyobjloader 提供的宏关闭缓存版本中与当前 MSVC 不兼容的 fast_float 路径。

tinyobjloader 的头文件和许可证已放入 `third_party/tinyobjloader`，构建不依赖 `out` 缓存和联网下载。
